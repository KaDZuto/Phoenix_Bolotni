# Phoenix_Bolotni 🐦

Система акустической классификации голосов птиц фауны Российской Федерации (преимущественно околоводных и болотных биотопов) на базе глубокого обучения (EfficientNet-B0) по лог-мел-спектрограммам.

---

## ⚠️ Важное разграничение функционала: модель НЕ предсказывает погоду

1. **Модель решает строго одну задачу — определение вида птицы по аудиозаписи.** Нейросеть физически не умеет предсказывать погоду и не замеряет гидрологический режим водоемов.
2. **Биоиндикация заболоченности** вынесена в отдельный модуль [`bioindicator/`](bioindicator/). Степень заболоченности может рассчитываться как вспомогательный орнитологический индекс по составу зарегистрированных видов-индикаторов. Веса приуроченности к водно-болотным угодьям (`wetland_affinity`) намеренно оставлены пустыми (`null`) в `bioindicator/species_weights.json`, так как их калибровка должна проводиться профессиональным биологом/экологом.
3. **Метеорологический контекст** (`bioindicator/weather_client.py`) — это внешняя интеграция с публичным API Open-Meteo по координатам и дате записи, служащая контекстом для орнитологических отчетов, а не предсказанием искусственного интеллекта.

## 🎧 Фоновый шум (`_noise`) и порог уверенности

В датасете разрешена служебная подпапка `_noise` (ветер, дождь, шум города, человеческая речь, звуки шагов, ветки). Она обучается как отдельный класс.

### Источники для сбора фонового шума
- Датасет [ESC-50](https://github.com/karolpiczak/ESC-50) (категории природного и городского шума: ветер, дождь, шаги).
- [Freesound](https://freesound.org/) с фильтром по лицензиям Creative Commons (CC0 / CC-BY).
- Собственные "пустые" полевые записи тишины и фонового шума болотных и лесных угодий без голосов целевых птиц.

### Логика отсечки в `inference.py` и перенос в Android/сервер
- Если максимальная вероятность (Top-1) принадлежит классу `_noise`, или Top-1 вероятность **ниже порога** (по умолчанию `0.6`), результат считается неопределенным: `"unknown/uncertain"`.
- **Как перенести в Android (Kotlin) / ONNX Runtime:**
  1. Выполнить прямой проход ONNX-модели, получить массив логитов размера `[1, NUM_CLASSES]`.
  2. Применить операцию Softmax: $P_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$.
  3. Найти индекс с максимальной вероятностью `max_idx` и соответствующую уверенность `max_prob`.
  4. Если `classes[max_idx] == "_noise"` или `max_prob < 0.60`:
     - Отображать пользователю: *"Птица не определена / фоновый шум"* (не предлагать птицу наугад).
  5. Иначе отображать название вида и уверенность.

## ⚙️ Единый контракт конфигурации (`model_config.json`)

Для согласованной работы серверного распознавателя, скриптов обучения и мобильного Android-клиента параметры препроцессинга и скользящего окна зафиксированы в [`model_config.json`](model_config.json):

```json
{
  "target_sr": 32000,
  "n_fft": 1024,
  "hop": 320,
  "n_mels": 128,
  "clip_seconds": 5.0,
  "noise_class_slug": "_noise",
  "confidence_threshold": 0.6,
  "window_stride_sec": 2.5,
  "window_count_for_vote": 3,
  "min_agree_windows": 2,
  "tta_time_shift_ms": [-200, 0, 200]
}
```

### Спецификация многократной проверки (Window Voting)
При обработке непрерывного полевого аудиопотока одиночный всплеск на одном окне легко может быть случайным артефактом. Реализованный алгоритм:
1. Нарезка аудио на окна по 5.0 секунд с перекрытием (шаг `2.5` сек).
2. (Опционально) Test-Time Augmentation (TTA) со сдвигами [-200мс, 0мс, +200мс] и усреднением вероятностей.
3. Вид считается подтвержденным, только если он признан доминирующим как минимум в `min_agree_windows` (2) из последних `window_count_for_vote` (3) окон.

## 🔍 Известные ограничения модели

- **Single-label классификация:** текущая версия модели предполагает наличие одного доминирующего вида в 5-секундном окне (не является multi-label детектором смешанных полифонических хоров птиц).
- **Фиксированное окно анализа:** препроцессинг нормализует звук до 5.0 секунд на частоте 32 кГц.
- **Локальные диалекты:** пение птиц может различаться между популяциями Европы, Сибири и Дальнего Востока; при сборе новых данных рекомендуется фильтровать записи по регионам РФ.
- **Влияние сильного ветра и перегрузок микрофона:** низкочастотные порывы ветра требуют использования ветрозащиты на микрофонах в полевых условиях.

## 🚀 Установка и запуск

### 1. Установка окружения

```bash
git clone https://github.com/KaDZuto/Phoenix_Bolotni.git
cd Phoenix_Bolotni

python3 -m venv venv
source venv/bin/activate

# Установка зависимостей проекта
pip install --upgrade pip
pip install -r requirements.txt -r requirements-dev.txt
```

### 2. Подготовка датасета (с защитой от утечек)

Скрипт проверяет валидность видов против Whitelist РФ и выполняет **групповой сплит по recording_id** (части одной длинной записи никогда не попадут одновременно в train и val/test):

```bash
python prepare_data.py --data-dir dataset --artifacts-dir artifacts
```

### 3. Обучение модели

```bash
python train.py --epochs 12 --batch-size 32 --lr 3e-4 --device cpu
```

После завершения обучения в папке `model_output/` формируются:
- `best.pth` — веса модели с лучшим Val Macro-F1.
- `classification_report.json` и `classification_report.csv` — детальные метрики точности, полноты и F1 по каждому классу.
- `confusion_matrix.png` и `confusion_matrix.csv` — матрица ошибок.
- `training_history.csv` — динамика Loss и F1 по эпохам.
- `run_config.json` — конфигурация запуска и версии библиотек для воспроизводимости.
- Таблица худших по F1 классов в консоли (для целевого добора данных).

### 4. Инференс и распознавание

**Одиночный файл:**
```bash
python inference.py --audio path/to/sample.wav --model models/best.pth --conf-threshold 0.6
```

**Скользящее окно с голосованием для длинной записи:**
```bash
python inference.py --audio path/to/long_field_recording.wav --sliding-window --tta
```

### 5. Сбор данных с Xeno-canto (фауна РФ)

```bash
# Сухой прогон (поиск доступных записей в РФ)
python scripts/collect_xenocanto.py --species anas_platyrhynchos --dry-run

# Скачивание записей с сохранением атрибуции
python scripts/collect_xenocanto.py --species anas_platyrhynchos --max-per-species 5
```

### 6. Запуск тестов

```bash
pytest -q
```
